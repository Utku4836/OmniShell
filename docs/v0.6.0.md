# OmniShell 0.6.0

The home screen keeps the ASCII wordmark and places larger tool names in a compact two-column list. Short windows scroll the list, including when navigating from the keyboard.

## Windows and terminal rendering

- Switch CLI opens the chosen profile in another window and preserves the current session. Selecting an already running profile focuses its window.
- A CLI exit returns the primary window to the home screen. Auxiliary windows close.
- The context menu includes Minimize. Window opening, restoration, and minimization use short fades with a reduced-motion variant.
- Context menus use a black surface. The submenu is positioned independently and stays within the viewport, with scrolling when needed.
- Terminal text has a small inset from the rounded window edge. The scroll thumb is narrow and uses muted colors.
- Narrow perimeter canvases fill unused pixels around the terminal grid from neighboring cells. This layer does not infer or replace the terminal's default theme from a dialog, selection, or diff background.

## Installation and preferences

Installers select an explicit release and compare the installed version before reporting completion. npm-based CLIs receive a profile-local global-install prefix, so their own npm update commands target the runtime OmniShell launches. Antigravity uses its official release manifest and checksum rather than a bootstrap that skips an existing executable.

Automatic checks run while OmniShell is open. They update installed, idle profiles and defer active profiles. Release requests are shared across profiles and checks are cached. Progress and completion use the same profile state for Default and custom profiles, including elapsed time and the current stage.

Closing a session first allows the CLI to exit and write its preferences, with a bounded forced-termination fallback. Claude's stored effort preference is reapplied at launch. Amp's generated Full Permission configuration retains preference changes without copying the injected permission into the normal settings file.

A native Windows event hook suppresses console-class windows belonging to watched CLI processes. It does not hide unrelated application windows.

## Rendering differences between terminals

Terminal hosts choose fonts, palettes, and supported color queries. A CLI can therefore draw differently in OmniShell and a Windows console even when both run the same executable. Codex also uses the terminal's background information when drawing its composer. The application's earlier content-based background detector amplified that difference by applying a gray UI region to the whole terminal; that detector has been removed.

The CLI's own ANSI styling remains intact. Provider-specific settings still follow the CLI's semantics; for example, Claude documents `max` effort as session-only, while other supported effort levels persist.

References: [xterm terminal options](https://xtermjs.org/docs/api/terminal/interfaces/iterminaloptions/), [Codex composer theme behavior](https://github.com/openai/codex/issues/14105), [Claude model configuration](https://code.claude.com/docs/en/model-config).
