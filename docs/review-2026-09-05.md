# OmniShell code review — September 5, 2026

## Scope

The v0.5.0 changes cover profile launch settings, optional sharing, recoverable deletion, Switch CLI, and terminal backgrounds. This note describes the persistence and lifecycle decisions behind those changes.

## Changes

- Profile persistence rolls back in-memory changes when a disk write fails. Access errors no longer cause valid metadata to be classified as corrupt. Reads wait for pending writes, and temporary files are cleaned up.
- Stop and replacement launches invalidate pending startup requests before they can create a late PTY. Profiles cannot be deleted or reconfigured while starting, running, or saving exit data.
- Shutdown and subsequent sessions wait for CLI exit and shared-data publication, replacing the fixed 250 ms delay. Enabling sharing consumes the common copy instead of replacing it with stale local data.
- SQLite transfers use database backups that include committed WAL data. Live sidecars are not copied separately. Sharing rejects symbolic links and junctions and reports access failures. See the [Node.js SQLite backup documentation](https://nodejs.org/api/sqlite.html).
- Qwen receives `--approval-mode yolo` at launch without changing its shared configuration. Legacy permission backups are restored. Malformed Amp JSON is rejected instead of becoming an empty permissive configuration. See the [Qwen CLI documentation](https://qwenlm.github.io/qwen-code-docs/en/users/features/headless/).
- Failure to start `taskkill` falls back to the PTY termination method.
- Clicking an already hovered Switch CLI menu keeps it open. Its submenu stays inside the window and supports keyboard opening.
- The CSP permits styles generated by xterm while retaining the local-only script policy. Reduced-motion rules no longer unintentionally animate every position and size change.

## Local verification commands

- `npm test`: persistence failures, SQLite WAL transfers, permission settings, and terminal lifecycle races.
- `npm run check`: JavaScript syntax.
- PowerShell parser checks for installer scripts.
- `npm run test:ui`: real Electron, preload, IPC, ConPTY, and SQLite sharing under a temporary data root; Switch CLI hover/click, profile selection, RGB diff backgrounds, and responsive submenu positioning. Screenshots are written to `out/review/`.
- `npm run health`: installed CLI version checks through ConPTY.
- `npm audit --omit=dev --audit-level=moderate`: production dependency audit.
- `npm run dist -- --config.directories.output=../dist/review`: portable Windows build.

## Operational limits

Profiles using the same shared category run one at a time. Independent profiles can still run concurrently. This prevents concurrent copies from overwriting each other's shared data.

CLI version checks do not verify authenticated conversations or resuming a real conversation across every provider. Provider-specific session and configuration formats require account-backed end-to-end validation.
