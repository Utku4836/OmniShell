# OmniShell 0.6.3

This release simplifies local storage and makes profiles easier to manage. Each CLI has one installation, while its profiles keep separate accounts, settings, workspaces, logs, and temporary files.

### Profiles and storage

- Profiles now live in named folders such as `system/Codex/Profiles/Work`. The Default profile uses the same layout.
- Each profile has a `(Profile name)-(CLI name).Toml` file for OmniShell settings. CLI configuration remains in the format expected by the CLI.
- Existing profile data moves into the new layout on startup. Interrupted moves can resume, and conflicting destinations are left untouched.
- Renaming a profile moves its folder, renames its TOML file, and updates old folder paths in recognized CLI settings. If a change fails, OmniShell restores the previous name and settings.
- Deleting a custom profile moves its complete folder to recoverable trash.

### Sharing and daily use

- Sessions, model data, configuration, skills, and MCP servers have separate sharing switches. Sharing remains within the same CLI.
- The profile picker has a visible **OPEN** action and clearer descriptions for sharing options.
- CLI updates use the shared installation, and successful installations remove their temporary downloads.

Download `OmniShell.exe` below and run it directly. Existing profiles are carried forward when the new version starts.
